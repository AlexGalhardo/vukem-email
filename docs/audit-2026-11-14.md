# Audit 2026-11-14: gap to a minimal listmonk

Read-only audit of `main` at `f30adb6` (vukem v0.41.0). Nothing here is implemented: the owner runs the grilling first (ROADMAP 10.a). Line numbers refer to that commit.

Local validation of the audited tree: `go vet ./...` clean, `go test -count=1 ./...` green (one unexplained red in the very first cold run, six later runs green), `npm run check`, `npm run typecheck` and `npm run build` green, `gofmt -l` clean, `npm run lint` red (item M1).

## High

- **H1. A permanent send failure leaves the delivery queued forever** (`app/jobs/delivery.go:95-103`, `:163-170`). `resendError` wraps `queue.ErrPermanent` for any 4xx except 408/409/429 (`app/newsletter/send.go:253-263`), so the queue stops retrying on attempt 1. The settle code only writes `failed` when `attempt.Last()`, which is `Number > MaxRetries` (`vukem/queue/attempt.go:38`) and is false on attempt 1. The delivery stays `queued`, the campaign never reaches `completed`, and `CampaignHealth` reports `stalled` after 15 minutes. Proposal: settle as `failed` when `errors.Is(err, queue.ErrPermanent) || attempt.Last()`; add a test with a fake Resend returning 422.
- **H2. Send fans out in one transaction, one row and one dispatch at a time** (`newsletter.go:444-496`, create at `:475`). Large lists mean a long lock on the campaign row and a transaction that grows with the list. Proposal: use `orm` bulk create for deliveries (`vukem/orm/bulk.go`) and batch dispatch; measure with `tests/perf_test.go` at 50k subscribers.
- **H3. No open and click tracking.** Needed for the dashboard metrics of 10.b. Options for the grilling: Resend `email.opened` and `email.clicked` events (cheap, no own pixel, but Resend click tracking rewrites links on its domain and needs the domain set up) or own pixel and redirect endpoints (privacy and Apple MPP noise, signed redirect to avoid an open redirect). Either way: a `delivery_events` table and per-campaign counters.
- **H4. No token API.** Hexascore and eletroradar (ROADMAP 10.c) need to add subscribers and read stats from the compose network. Public `POST /subscribe/{slug}` exists, but nothing authenticated. Proposal: project-scoped API tokens, hashed at rest, rate limited; reuse the controllers behind a token middleware instead of the Google session.
- **H5. Mailer errors from the renderer are reported as user errors** (`app/newsletter/renderer.go:33-36`). Timeout (15 s), a missing `node`, an OOM kill (`--max-old-space-size=128`) and a real syntax error all return 422 "Invalid content", and stderr is discarded. This hides infrastructure failures from the admin and from logs, and a slow cold Node start under load can look like a content error (one unreproduced red in the first cold `go test ./...`). Proposal: separate `context.DeadlineExceeded` and exec failures (500 plus log of stderr) from validation errors; test the timeout.

## Medium

- **M1. Root `npm run lint` fails and CI never runs it** (`.github/workflows/ci.yml:30-45` runs `npm run check` and the `site` lint only). Biome reports unsorted imports in `resources/js/**`, `useImportType` in `components/ui/*.tsx` and a label without a control (exit code 1). Proposal: `biome check --write`, fix the label by hand, add `npm run lint` to the CI job.
- **M2. Soft bounces and delays are ignored** (`webhooks.go:34`, `:44`). Repeated soft bounces never suppress. Proposal: store each bounce (`bounces` table: subscriber, delivery, type, raw reason) and suppress after N soft bounces in a window (listmonk default 2-3).
- **M3. Webhook route disappears silently without `RESEND_WEBHOOK_SECRET`** (`routes/web.go:133-139`). In production this means no bounce or complaint handling and no log line. Proposal: fail boot in production when the secret is empty, log a warning elsewhere.
- **M4. Webhook state is last-writer-wins.** Status moves only from `queued/accepted/delivered` (`webhooks.go:40`), so a `complained` after `bounced`, or events out of order, lose data; the ROADMAP P0 asks for tests of out-of-order events and none exist. Suppression is check-then-insert (`:51-60`) with a unique index behind it (`database/migrations/suppressions.go:12`), so a duplicate concurrent event returns 500 on the unique violation; Svix retries make it converge, but handle the conflict.
- **M5. Admin unsubscribe and token unsubscribe overwrite any status** (`newsletter.go:247`, `:572`). A `suppressed` subscriber (hard bounce, complaint) becomes `unsubscribed`; the `suppressions` row still blocks sending, but the dashboard loses the reason. Proposal: update only from `pending` or `confirmed`.
- **M6. `site/Dockerfile:9` serves docs with nginx.** The owner rule is Caddy only; Dependabot PR #12 bumps that nginx tag. Proposal: move to a pinned Caddy image and close #12 afterwards.
- **M7. Subscribers have no name, attributes or tags** (`app/models/newsletter.go:21-31`) and campaigns have no segment, so there is no personalization (`{{name}}`) and no targeting. Blocks ROADMAP P1 segments.
- **M8. Single admin hardcoded** (`newsletter.go:30`, `routes/web.go:110`). Fine for the personal product; decide in the grilling whether 10.c needs more than one operator.
- **M9. Rate limiting is in-process** (`routes/web.go:91`, `ratelimit.NewMemory`). With more than one replica the 10/min limit multiplies. Fine for one container; note it before scaling.

## Low

- **L1. `LIKE` wildcards in subscriber search are not escaped** (`newsletter.go:332`): `%` and `_` in the term widen the match, and `%term%` cannot use an index. Escape, or switch to prefix search.
- **L2. The delivery worker runs about six queries per message** (subscriber, campaign, suppression count, project, key derivation, then updates; `app/jobs/delivery.go:91-171`). Cache project and campaign per batch if throughput matters.
- **L3. Export streams after headers are sent** (`newsletter.go:536-569`): an error mid-stream gives a truncated 200. Acceptable; add the status filter and the `created_at` range when import lands.
- **L4. Confirmation and unsubscribe URLs force `https://` plus the project domain** (`newsletter.go:164`, `app/jobs/delivery.go:151`, `app/newsletter/send.go:266`). Local end-to-end tests with real links need a TLS proxy; make the scheme configurable via `APP_URL` for dev.
- **L5. Campaigns can only be created or edited as draft** (`newsletter.go:401-419`): no delete, no duplicate, no cancel of a queued campaign.
- **L6. `go test -race` is not runnable on this Windows host** (needs cgo); CI covers it on Linux. Not verified locally.

## Missing tests

- Permanent Resend error settles the delivery and completes the campaign (H1).
- Renderer timeout and missing Node are not reported as 422 (H5).
- Webhook events out of order and soft bounce (M2, M4); duplicate suppression insert.
- Unsubscribe never downgrades a `suppressed` subscriber (M5).
- `app/jobs`, `app/models` and `app/controllers` have no package-level tests; coverage is only through `tests/` (32 tests). The Postgres workflow test is skipped without `TEST_DATABASE_URL` (CI sets it).
- Send fan-out at scale beyond `tests/perf_test.go`.
- Root frontend lint in CI (M1).

## Suggested grilling order

1. Lists model: keep project = list or add lists and memberships (affects schema for everything below).
2. Tracking source: Resend events or own endpoints (H3).
3. API tokens and scopes (H4), driven by the hexascore and eletroradar integration.
4. Import with consent rules, then segments (M7).
5. Templates and scheduling.
